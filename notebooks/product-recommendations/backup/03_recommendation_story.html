02 / FEATURE ENGINEERING

Turn the histories into a table of 1s and 0s.

A row is a customer. A column is a product. This is the customer-product matrix.

One cell, one question

1 or 0

Did this person ever buy this product in the training period?

Asha's three red bags still become 1. A repeat purchase does not add extra weight in this binary model.

0 does not mean dislike.
The customer may never have seen the product.

The features are purchase signals. Product photos, names, prices, and descriptions are not inputs to this similarity calculation.

03 / MODEL TRAINING: COMPARE PRODUCTS

Compare two product columns.

Red bag and strawberry bag share two buyers. Cosine similarity adjusts that overlap for the number of buyers each product has.

Red bag buyers3
Strawberry bag buyers2
Shared buyers2
2√(3 × 2)≈0.816

For binary columns:
shared buyers / square root of (buyers of A × buyers of B).

0 = no shared buyers.
1 = identical buyer groups.

Two 0s do not add similarity. The numerator counts shared purchases, not shared non-purchases.

Similarity is a pattern in behavior, not a visual match. A bag and a cake stand can have a link if some people bought both.

04 / MODEL TRAINING: SAVE THE LINKS

Keep the strongest neighbors.

Repeat the comparison for every product. Ignore its match with itself, then keep its strongest positive links.

The saved links are the model.

Top 3

This small example saves up to three neighbors per product. The real lesson saves up to 15.

Learn once, reuse the links

Here, "learning" means calculating and storing similarities. There is no neural network or repeated error-correction loop.

Why keep only a few links?

It limits storage and weak connections. How many to keep is a model choice to test. Raw cosine is symmetric, but keeping only the best links per source can make the stored links one-way.

Two different tables: the first table connects customers to products. The learned table connects products to other products.

05 / MODEL PREDICTION: ADD THE EVIDENCE

A new shopper arrives. Add the saved links.

This shopper bought a red bag and a strawberry bag. Each purchase contributes its saved similarity to every candidate product.

Lunch bag gets two contributions

0.816 + 0.500
= 1.316

The red bag and the strawberry bag both point to the lunch bag. Those weights add together.

1.316 is not a probability. This score can exceed 1. It is only used to order candidates.

Same model, different shopper: different purchase histories activate different saved links. No similar-customer search or new training is needed at this step.

06 / MODEL PREDICTION: FILTER AND RANK

Remove bought items. Recommend what remains.

This is a discovery task: do not recommend products already in the shopper's history. Sort the remaining scores from largest to smallest.

      07 / BACK TO THE REAL NOTEBOOK

      Same recipe. A much larger table.

      The real lesson uses item-item collaborative filtering with cosine similarity, built from the UCI Online Retail II purchase records.

      Learn from past data
      01Build the binary customer-product matrix
      02Compare the product columns
      03Save each product's strongest links
      Recommend for a shopper
      01Find links from purchased products
      02Add scores and exclude bought products
      03Return the highest-ranked remaining items
      Earlier purchases: learn the links
      Later purchases: check the recommendations

      Validation asks: did any of the top 10 recommendations appear among that customer's later, previously unpurchased products? Future purchases must not be used to build the links.

      Too little history? Fewer than five distinct purchases means a generic fallback, not a personalized claim. The real simulator uses recent-revenue products, then popularity if needed; fallback also fills empty slots.

      The model predicts useful product rankings, not a customer's reasons, purchase probability, or response to a discount.
